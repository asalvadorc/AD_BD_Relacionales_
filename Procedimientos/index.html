    Funciones y procedimientos almacenados¶

    Entorno de los ejemplos

    Los ejemplos Kotlin de esta página se realizan en el proyecto BDRelacionales, dentro del paquete Postgres, y utilizan la base de datos local geo.

    Reutiliza el objeto DatabaseLocal definido en Postgres/DatabaseLocal.kt. Las funciones y procedimientos SQL deben crearse previamente en geo desde DBeaver.

    Tanto las funciones como los procedimientos almacenados son bloques de código que se guardan en el servidor de la base de datos y que encapsulan una serie de instrucciones SQL.

    Recorrido Se ejecuta con Finalidad principal
    Función SELECT Calcular y devolver un resultado
    Procedimiento CALL Ejecutar una acción sobre la base de datos
    Kotlin JDBC Invocar funciones y procedimientos ya creados

    Se usan para:

    • Reutilizar operaciones complejas
    • Organizar mejor la lógica de negocio
    • Mejorar el rendimiento (menos tráfico entre app y BD)
    • Mantener la integridad de datos

    Diferencia entre Funciones y Procedimientos

    Una función está diseñada para calcular y devolver un resultado. Se puede usar directamente dentro de una consulta SQL como parte de un SELECT, WHERE, ORDER BY, etc. Las funciones siempre devuelven un valor, que puede ser escalar (un número, texto...), una fila o una tabla.

    Un procedimiento sirve para ejecutar acciones dentro de la base de datos, como insertar registros, modificar datos o gestionar operaciones en bloque. No devuelve un valor directamente (aunque puede usar parámetros de salida), y se ejecuta con CALL, no con SELECT.

    Función 

    graph TD
    A(["Llamada: SELECT func()"]) --> B["Ejecuta Lógica"]
    B --> C{"Devuelve Valor"}
    C --> D["Uso en SQL"]

    Procedimiento 

    graph TD
    E(["Llamada: CALL proc()"]) --> F["Ejecuta Acción"]
    F --> G[("Modifica BD")]
    G -.-> H["Sin retorno directo"]

    Nota

    SQLite no soporta funciones ni procedimientos almacenados como lo hacen bases de datos como PostgreSQL, MySQL u Oracle. Sin embargo, puedes simular su comportamiento mediante funciones definidas en la aplicación, o vistas y triggers.

    Las funciones (FUNCTION) y los procedimientos (PROCEDURE) no se crean desde el lenguaje Kotlin, ya que son elementos propios del sistema gestor de bases de datos (SGBD), en este caso PostgreSQL. Para definirlos, se utiliza SQL y se ejecutan directamente sobre la base de datos a través de un cliente SQL.

    Una vez que las funciones o procedimientos están creados en la base de datos, se pueden utilizar perfectamente desde Kotlin a través de JDBC, igual que se hace con cualquier consulta SQL:

    • Las funciones se invocan con SELECT nombre_funcion(...)
    • Los procedimientos se llaman con CALL nombre_procedimiento(...)

    Y desde Kotlin, se gestionan mediante objetos como PreparedStatement y CallableStatement.

    🤔 Comprueba tu comprensión

    Si te piden crear una funcionalidad para subir un 10% el sueldo a todos los empleados de un departamento, y otra para calcular cuál es el sueldo medio actual de dicho departamento, ¿qué usarías en cada caso?

    Ver respuesta
    • Para subir el sueldo, usarías un Procedimiento Almacenado (se llama con CALL), ya que su objetivo principal es ejecutar una acción que modifica los datos en la base de datos (un bloque de actualizaciones).
    • Para calcular el sueldo medio, usarías una Función (se llama con SELECT), ya que su objetivo es realizar un cálculo y devolver un valor o resultado que la aplicación necesita leer.

    🔹 Funciones (FUNCTION)¶

    Una función en PostgreSQL es un bloque que:

    • Puede aceptar parámetros
    • Devuelve siempre un valor (escalar, tabla o compuesto)
    • Se puede usar en consultas SQL (SELECT, WHERE, etc.)
    • Puede tener IN, OUT, INOUT

    Sintaxis básica en PostgreSql

        CREATE [OR REPLACE] FUNCTION nombre_funcion(parámetros)
    RETURNS tipo_de_dato
    LANGUAGE plpgsql
    AS $$
    BEGIN
        -- instrucciones
        RETURN valor;
    END;
    $$;
    Tipo de retorno ¿Qué devuelve? Ejemplo de uso
    INTEGER, TEXT, etc. Un único valor escalar RETURNS INTEGER
    RETURN x * x;
    TABLE(...) Una tabla (varias columnas y filas) RETURNS TABLE(codi TEXT, nom TEXT)
    RETURN QUERY ...
    SETOF INTEGER Un conjunto de valores escalares RETURNS SETOF INTEGER
    RETURN NEXT i;
    SETOF RECORD Muchas filas con estructura dinámica RETURNS SETOF RECORD
    %ROWTYPE Una fila con la estructura de una tabla existente RETURNS institut%ROWTYPE
    SELECT * INTO reg ...
    RECORD Una sola fila con columnas genéricas RETURNS RECORD
    SELECT ... INTO resultado;
    Tipo personalizado Una estructura definida con CREATE TYPE RETURNS tipo_personalizado

    Los siguientes ejemplos se han creado utilizando el cliente SQL DBeaver y la base de datos local geo.

    Funciones que devuelve un valor:

    Ejemplo en SQL: Función que devuelve el cuadrado de un número.

        CREATE OR REPLACE FUNCTION cuadrado(x INTEGER)
    RETURNS INTEGER -- (1)!
    AS $$
    BEGIN
        RETURN x * x; -- (2)!
    END;
    $$ LANGUAGE plpgsql;
    1. RETURNS declara el tipo del valor que entregará la función.
    2. RETURN finaliza la función devolviendo el resultado calculado.

    La llamada desde SQL sería:

        SELECT cuadrado(5);  --Devuelve 25

    En Kotlin la llamada a la función sería:

    Ejemplo_cuadrado.kt

            fun main() {

            DatabaseLocal.getConnection().use { conn ->
                val sql = "SELECT cuadrado(?)" // (1)!

                conn.prepareStatement(sql).use { stmt ->
                    stmt.setInt(1, 6) // (2)!
                    val rs = stmt.executeQuery() // (3)!

                    if (rs.next()) {
                        val resultado = rs.getInt(1) // (4)!
                        println("El cuadrado de 6 es: $resultado")
                    }
                }
            }
        }
    1. Las funciones PostgreSQL que devuelven valores se invocan desde Kotlin mediante SELECT.
    2. El parámetro JDBC se envía como argumento de la función.
    3. El valor devuelto llega dentro de un ResultSet de una fila.
    4. La primera columna contiene el resultado escalar producido por cuadrado.

    Fucniones que devuelven una tabla

    Ejemplo en SQL: Función que devuelve todos los institutos junto con su población y comarca.

            CREATE OR REPLACE FUNCTION obtener_instituts()
        RETURNS TABLE ( -- (1)!
            codi TEXT,
            nom TEXT,
            municipi TEXT,
            comarca TEXT
        )
        AS $$
            SELECT 
                i.codi,
                i.nom,
                p.nom AS municipi,
                c.nom_c AS comarca
            FROM institut i
            JOIN poblacio p ON i.cod_m = p.cod_m -- (2)!
            JOIN comarca c ON p.nom_c = c.nom_c
            ORDER BY comarca, municipi;
        $$ LANGUAGE sql;
    1. RETURNS TABLE define los nombres y tipos de las columnas que expondrá la función.
    2. La consulta interna genera las filas que la función devolverá al invocarla.

    La llamada desde SQL sería:

            SELECT * FROM obtener_instituts();

    En Kotlin la llamada a la función sería:

    Ejemplo_fun_obtener_institutos.kt

            fun main() {

           DatabaseLocal.getConnection().use { conn ->
                val sql = "SELECT * FROM obtener_instituts()"

                conn.prepareStatement(sql).use { stmt ->
                    val rs = stmt.executeQuery()
                    while (rs.next()) {
                        val codi = rs.getString("codi")
                        val nom = rs.getString("nom")
                        val municipi = rs.getString("municipi")
                        val comarca = rs.getString("comarca")

                        println("Institut: $codi - $nom ($municipi, $comarca)")
                    }
                }
            }
        }

    Fucniones que aceptan filtros como parámetros

    Ejemplo en SQL: Función que devuelve los institutos de una comarca.

            CREATE OR REPLACE FUNCTION instituts_de_comarca(p_nom_c TEXT)
        RETURNS TABLE (
            codi TEXT,
            nom TEXT,
            municipi TEXT,
            comarca TEXT
        )
        AS $$
            SELECT 
                i.codi,
                i.nom,
                p.nom AS municipi,
                c.nom_c AS comarca
            FROM institut i
            JOIN poblacio p ON i.cod_m = p.cod_m
            JOIN comarca c ON p.nom_c = c.nom_c
            WHERE c.nom_c = p_nom_c -- (1)!
            ORDER BY municipi;
        $$ LANGUAGE sql;
    1. El parámetro p_nom_c se utiliza dentro de la consulta para filtrar el resultado de la función.

    La llamada desde SQL sería:

            SELECT * FROM instituts_de_comarca('Plana Baixa');

    En Kotlin la llamada a la función sería:

    Ejemplo_fun_instituts_de_comarca.kt

            fun main() {

            DatabaseLocal.getConnection().use { conn ->
                val sql = "SELECT * FROM instituts_de_comarca(?)" // (1)!

                conn.prepareStatement(sql).use { stmt ->
                    stmt.setString(1, "Plana Baixa") // (2)!
                    val rs = stmt.executeQuery()
                    while (rs.next()) {
                        val codi = rs.getString("codi")
                        val nom = rs.getString("nom")
                        val municipi = rs.getString("municipi")
                        val comarca = rs.getString("comarca")

                        println("Institut: $codi - $nom ($municipi, $comarca)")
                    }
                }
            }
        }
    1. El argumento de la función se representa con un parámetro JDBC para evitar construir SQL dinámico.
    2. setString asigna el nombre de la comarca al parámetro de entrada de PostgreSQL.

    🔹 Procedimientos (PROCEDURE)¶

    Los procedimientos no devuelven valores directamente, a diferencia de las funciones, pero pueden tener parámetros de entrada (IN), salida (OUT) o ambos (INOUT). Se utilizan para realizar tareas como:

    • Inserciones o actualizaciones complejas
    • Validaciones
    • Operaciones en bloque
    • Ejecución de lógica con control de flujo
    • Agrupación de instrucciones dentro de una transacción

    Sintaxis básica en PostgreSQL

        CREATE [OR REPLACE] PROCEDURE nombre_procedimiento(
        [[IN | OUT | INOUT] nombre_parámetro tipo],
        ...
    )
    AS $$
    BEGIN
        -- cuerpo del procedimiento
    END;
    $$ LANGUAGE plpgsql;

    Ejemplo en SQL: Procedimiento que inserta un nuevo instituto y muestra un aviso.

            CREATE OR REPLACE PROCEDURE insertar_institut_resultado(
            IN p_codi VARCHAR,
            IN p_nom VARCHAR,
            IN p_cod_m INTEGER,
            OUT resultado TEXT -- (1)!
        )
        AS $$
        BEGIN
            -- ¿Municipio existe?
            IF NOT EXISTS (SELECT 1 FROM poblacio WHERE cod_m = p_cod_m) THEN -- (2)!
                resultado := 'MUNICIPIO_NO_ENCONTRADO';
                RETURN;
            END IF;

            -- ¿Instituto ya existe?
            IF EXISTS (SELECT 1 FROM institut WHERE codi = p_codi) THEN
                resultado := 'EXISTENTE';
                RETURN;
            END IF;

            -- Insertar instituto
            INSERT INTO institut (codi, nom, cod_m) -- (3)!
            VALUES (p_codi, p_nom, p_cod_m);

            resultado := 'INSERTADO';
        END;
        $$ LANGUAGE plpgsql;
    1. El parámetro OUT permite comunicar a la aplicación el resultado de la operación.
    2. El procedimiento valida los datos en el servidor antes de modificarlos.
    3. La inserción solo se ejecuta si se cumplen las reglas comprobadas anteriormente.

    La llamada desde SQL sería:

            CALL insertar_institut_resultado('I999', 'Institut Experimental', 12028, NULL);

    En Kotlin la llamada al procedimiento sería:

    Ejemplo_pro_insertar_institut_resultado.kt

            import java.sql.Types

        fun main() {
           DatabaseLocal.getConnection().use { conn ->
                val sql = "CALL insertar_institut_resultado(?, ?, ?, ?)"

                conn.prepareCall(sql).use { stmt -> // (1)!
                    stmt.setString(1, "I999")
                    stmt.setString(2, "Institut Experimental")
                    stmt.setInt(3, 12028)
                    stmt.registerOutParameter(4, Types.VARCHAR) // (2)!

                    stmt.execute() // (3)!

                    val resultado = stmt.getString(4) // (4)!
                    println("Resultado: $resultado")
                }
            }
        }
    1. Los procedimientos se invocan mediante CallableStatement, creado con prepareCall.
    2. Los parámetros de salida deben registrarse con su posición y tipo JDBC antes de ejecutar.
    3. execute() realiza la llamada al procedimiento almacenado.
    4. Tras la ejecución se recupera el valor asignado al parámetro OUT.

    📊 Resumen de diferencias entre función y procedimiento en PostgreSQL¶

    Característica FUNCIÓN (FUNCTION) PROCEDIMIENTO (PROCEDURE)
    🔁 Devuelve un valor ✅ Sí (con RETURN) ❌ No directamente
    📥 Parámetros de entrada (IN) ✅ Sí ✅ Sí
    📤 Parámetros de salida (OUT) ✅ Sí (como OUT, INOUT, o RETURNS) ✅ Sí (OUT, INOUT)
    📌 Se invoca con… SELECT nombre_funcion(...) CALL nombre_procedimiento(...)
    📊 Usable en consultas SQL ✅ Sí (puede ir en SELECT, WHERE, etc.) ❌ No
    🔄 Puede devolver tablas ✅ Sí (RETURNS TABLE o SETOF) ❌ No directamente
    🔁 Puede usar RETURN ✅ Obligatorio ❌ No se usa RETURN, sino solo CALL
    🧱 Uso típico Cálculos, validaciones, funciones reutilizables Procesos complejos, lógica de negocio, transacciones

    Comprueba tu comprensión¶

    1. ¿Por qué una función o procedimiento debe existir antes de invocarlo desde Kotlin?

    Ver respuesta

    Porque su código está almacenado y se ejecuta en PostgreSQL. Kotlin envía una sentencia para invocarlo, pero esa llamada no lo crea. Primero debemos definirlo en la base de datos mediante CREATE FUNCTION o CREATE PROCEDURE, por ejemplo desde DBeaver. Si no existe una función o procedimiento que coincida con el nombre y los tipos de los argumentos de la llamada, PostgreSQL devolverá un error.

    2. ¿Qué diferencia hay entre escribir una función Kotlin y crear una función almacenada en PostgreSQL?

    Ver respuesta

    Una función Kotlin forma parte de la aplicación y se ejecuta donde se ejecuta el programa. Puede acceder a la base de datos enviando sentencias mediante JDBC. Una función almacenada en PostgreSQL se define en la base de datos, por ejemplo en SQL o PL/pgSQL, y se ejecuta en el servidor. Kotlin puede invocarla mediante una consulta como SELECT nombre_funcion(...) y recoger su resultado. También puede ser utilizada por otras aplicaciones que tengan los permisos necesarios.
